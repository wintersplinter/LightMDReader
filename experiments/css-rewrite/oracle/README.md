# The screenshot oracle

The safety net for the CSS rewrite. It renders two fixture documents through the app's
own render path in every combination the style layer can produce, and writes one PNG per
combination. Identical pixels before and after a change means the change is invisible,
which is the whole contract of a structural rewrite.

**144 renders**: 2 fixtures x 2 widths (1100 / 640, so the 700px mobile block is crossed)
x 2 media (screen / print) x 3 themes (dark / light / brown) x 6 styles.

## Running it

These scripts run in the cloud container, not on the device — the project has no
Playwright and does not need one. Copy the app's static files to a scratch directory,
serve them over plain HTTP (the CSP is `default-src 'self'`, so `file://` misbehaves),
then:

```
node render.cjs  <out-dir>          # capture a set
python3 compare.py <a-dir> <b-dir>  # diff two sets, exit 1 if anything differs
node coverage.cjs                   # check the fixture still produces every styled element
```

Paths inside the scripts are container paths: `/opt/pw-browsers/chromium` for the browser
and `/home/claude/.npm-global/lib/node_modules/playwright` for the driver.

## The baseline is disposable

It is captured from committed code, so it can always be regenerated by checking out the
commit and re-running. Losing the PNGs costs a few minutes, not the work.

## Validated, not assumed

Before trusting it, it was checked three ways:

- **Self-test**: a set against itself reports identical.
- **Sensitivity**: a 0.01em nudge to Studio's h2 was caught, and correctly isolated to
  Studio and to the wide renders only — the narrow ones legitimately did not move,
  because the mobile block overrides that value.
- **Colour sensitivity**: a 1/255 change to one Graphite token was caught in all twelve
  Graphite renders.
- **Stability**: two consecutive captures of unchanged code are byte-identical, so a
  difference is never noise.

## Traps it works around

All of these have cost time in this project before:

- `emulateMedia({ media: 'screen' })` persists and silently overrides a later print pass,
  so the media is set explicitly for every capture.
- CDP does not fire `beforeprint`/`afterprint`, so PDF title pages never appear unless the
  events are dispatched by hand.
- Hiding `.sidebar` leaves its 280px grid column behind and squeezes the render to half
  width. `.layout` has to become a block too.
- A stale scratch copy of a CSS file produces confidently wrong numbers. Re-stage every
  file at the start of a round and sanity-check a known marker before trusting anything.

## What it cannot prove

The heading faces are system stacks (Corbel, Constantia, Bahnschrift, ...) that the
container does not have, so every render shows the fallback. That is fine for a
before/after diff — the fallback is identical on both sides — but it says nothing about
how the real faces set.
